# Biblioteca según voz, mensaje y función

Criterio confirmado por el usuario el 2026-09-30, durante la comparación de C y las dos referencias: nuestros videos duran habitualmente **15–30 segundos**. Pueden usar una música o dos según duración y contexto; no existe cuota ni cambio automático por cronómetro. Primero decidir qué función necesita cada idea. Una sola pista puede sostener varios momentos con entradas, variación de ganancia, selección de arreglo, retiros, silencio y efectos. Una segunda se justifica por un giro de intención que tenga espacio para asentarse.

La mezcla se trabaja dentro de las frases: anticipar palabras relevantes, conservar finales suaves, recuperar música cuando la idea lo permita y revisar la primera palabra tras una pausa. El ducking puede ayudar, pero no reemplaza las decisiones editoriales ni debe devolver el fondo en cada hueco.

Ambos se descargan de páginas oficiales con CC BY 4.0 y créditos. Los roles son propuestas editoriales, no lectura automática de emociones. No se certifican BPM/tonalidad o puntos de cambio que no se hayan medido. Ningún audio extraído de los videos de referencia se incorpora a la biblioteca para reutilización.

Ocho SFX originales se indexan por entrada, transición, detalle, énfasis, contraste, secuencia, retorno y cierre. Usar una identidad no garantiza percepción: revisar carácter, ganancia, ataque y cola contra la voz contemporánea y el MP4 exacto. Las variantes suaves y el feedback previo siguen en sus manifiestos; no se rehabilita un candidato descartado sin una nueva prueba explícita.

La primera tanda de tres pistas y la cama procedural se conservan en **Antecedentes y descartes**. El rechazo corresponde a los extractos presentados; no se presenta como escucha ni rechazo de canciones completas. Descargar/verificar licencia, probar un extracto, aprobar una mezcla y adoptar un recurso en toda la biblioteca son estados distintos.

Para incorporar un recurso: verificar procedencia/licencia → congelar archivo y hash → proponer función y carácter → preparar muestra → probar bajo voz real → registrar feedback por tramo/mezcla → adoptar con alcance explícito. No reemplazar versiones previas ni descargar grandes lotes sin necesidad. Ampliar cuando falte una función concreta; no prometer que tres pistas cubran todos los mensajes futuros.
