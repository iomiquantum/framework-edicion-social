# Visual Quality Director

Turn vague feedback such as “it looks amateur,” “like Paint,” “flat,” or “not current” into a specific diagnosis, a coherent visual system, and verified corrections.

## Start from evidence

1. Read applicable project rules and preserve existing versions.
2. Inspect the brief, design spec, storyboard, composition files, and any prior audit.
3. Review a contact sheet spanning the whole piece, then inspect the exact frames around defects. For moving faces or panels, sample early/middle/late; one still does not prove safety.
4. Separate three claims:
   - technical validity: files load, timelines seek, checks pass;
   - visual judgment: hierarchy, taste, legibility, continuity;
   - performance hypothesis: likely attention or retention effect, still unmeasured until publication data exists.

For the audit rubric and red flags, read [references/audit-checklist.md](references/audit-checklist.md).

## Require three review passes

For any revision whose purpose is to fix visual quality, complete three distinct passes before calling it ready:

1. **Diagnosis pass:** inspect a whole-piece contact sheet plus early/middle/late states of every scene; list actual overlaps, occlusions, weak hierarchy, empty zones, low contrast and caption/UI collisions.
2. **Correction pass:** implement the smallest coherent redesign, then rerun structural and visual checks. Do not silence a finding with an allow-marker unless the inspected layering is visibly intentional and legible.
3. **Delivery pass:** inspect frames extracted from the rendered MP4, including every short scene and both sides of transitions. Confirm captions at phone scale and compare against the diagnosis list.

A pass is not complete merely because an automated command succeeds. Preserve the evidence for all three passes and repeat the correction/delivery loop when a defect remains.

## Direct before decorating

State one creative concept that explains the palette, typography, composition, objects, and motion. Define:

- one dominant focal idea and one supporting focus per visual state;
- protected zones for face, graphics, captions, and platform UI;
- type roles with visibly different voices, not only different weights;
- semantic color roles with measured contrast;
- a small motion vocabulary tied to narrative changes;
- per-scene jobs and the handoff to the next scene.

Do not solve flatness by adding arbitrary elements. Replace weak boxes with larger, connected editorial objects; attach every connector to real endpoints; use overlap, depth, scale, and edge anchoring only when they strengthen the reading order.

## Protect people structurally

Treat the moving envelope of eyes, nose, mouth, chin, and gestures as unavailable space, with a practical margin. Separate the presenter and the editorial stage geometrically whenever overlays could intersect the face. Transparency is not a fix for occlusion.

Treat edit title-safe and destination-platform safe zones as different checks. Keep captions in a dedicated lane and prevent them from duplicating a large on-screen statement word for word.

## Use current practice carefully

When the user requests current practices, browse current authoritative sources. Prefer official platform guidance and accessibility standards. Translate each source into a concrete design decision and label platform advice as a hypothesis, not an algorithmic guarantee. Read [references/current-practices.md](references/current-practices.md) for the maintained evidence baseline.

## Implement only within scope

An audit or explanation does not authorize edits. When the user asks for changes:

- create a new version when preservation is requested;
- keep the previous version intact;
- update the new version’s design spec, storyboard, changelog, and review note;
- avoid changing the narrative meaning unless the user also authorizes script changes.

For HyperFrames projects, use the mandatory HyperFrames skills and follow [references/hyperframes-verification.md](references/hyperframes-verification.md). Do not render a final deliverable without explicit approval.

## Deliver

Report:

1. the primary visual diagnosis;
2. the creative direction and visual system;
3. defects and corrections by scene;
4. the verification evidence actually inspected;
5. unresolved human-review points;
6. claims that remain hypotheses;
7. the exact new-version or preview location.

Never say the user approved, viewed, heard, or validated something without evidence.
